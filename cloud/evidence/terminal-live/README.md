# Live Ptyxis capture method

These accepted PNGs are screenshots of a **real Ptyxis terminal window** in a private Xvfb X11 display, captured with `xwd` and converted losslessly to PNG by ImageMagick. The automation typed the actual commands into Ptyxis with `xdotool`. Each shell session was recorded continuously with `script -q -f`: [ptyxis-live.session](ptyxis-live.session) is the main unedited transcript, [ptyxis-repair.session](ptyxis-repair.session) contains shorter recaptures, and [ptyxis-pod.session](ptyxis-pod.session) contains the final pod-security recapture. Each accepted screenshot contains a `date -u` result, the `[GRP01]` prompt, command text, and visible output. A failed command remains visible as its actual error.

The session ran inside an isolated Linux UTS namespace whose **real** hostname was set to `atl-cloud-GRP01`; the physical host remained `morgoth`. This is a capture environment, **not a project VM**. The terminal application is Fedora GNOME's installed Ptyxis 49.3. The classic `gnome-terminal` executable was unavailable. The GNOME Wayland screenshot interface denied programmatic window capture, so a private Xvfb display was used. These are neither AWS console screenshots nor photographs of the user's physical desktop.

The capture script is [`../../capture_live_ptyxis.py`](../../capture_live_ptyxis.py), and its shell is [`../../live_ptyxis_shell.sh`](../../live_ptyxis_shell.sh). The commands query real AWS project resources or the local kind cluster; no output was synthesized. The demo secret command deliberately withholds its value *before printing*, so no image data was edited or redacted. The original `.session` may contain control sequences from the terminal but preserves the commands and output.

For repeatability, Xvfb, xwd, xdotool, libxdo, and xwininfo binaries were extracted from Fedora RPMs into `/tmp/grp01-x11` because system package installation required a sudo password. Those extracted binaries were copied to `/home/anouar/.local/share/grp01-x11`, and the capture script now points there. The recorded sessions used the original `/tmp` extraction before the copy. These tools are user-local, not installed system-wide.
