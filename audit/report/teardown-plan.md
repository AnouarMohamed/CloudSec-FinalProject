## Approval gate and proposed sequence

`AGENTS.md` rule 7 requires Anouar's approval before `terraform destroy` or deleting evidence-bearing buckets. Stopping CloudTrail also ends the audit feed; include that in the approval. First review and preserve evidence, then execute only the approved steps:

1. **Restore a non-root build identity and confirm scope.** Run `rtk proxy aws sts get-caller-identity --profile cloud`. Continue only when the ARN is an MFA-enabled IAM administrator, not `:root`. Save current raw reports, screenshots, transcripts, Terraform code, and the CloudTrail log objects. Export the logs outside Git with `rtk proxy aws s3 sync s3://cloud-trail-logs-grp01 /home/anouar/CloudTrail-archive-grp01 --profile cloud --region eu-west-3` and verify the local copy. Protect that local archive; it can contain account activity.
2. **After explicit approval**, stop new trail delivery with `rtk proxy aws cloudtrail stop-logging --name cloud-trail-grp01 --profile cloud --region eu-west-3`. Wait for in-flight delivery, repeat the S3 sync, and verify the archive again. This action creates an audit gap, so do it only at the end.
3. Inspect the two project buckets and their versions using `rtk proxy aws s3api list-objects-v2 --bucket cloud-trail-logs-grp01 --profile cloud --region eu-west-3`, `rtk proxy aws s3api list-object-versions --bucket cloud-trail-logs-grp01 --profile cloud --region eu-west-3`, and the corresponding `list-object-versions` command for `cloud-docs-grp01`. The docs bucket policy currently denies `ListBucket`; if listing is denied, review the policy and plan a temporary, narrowly scoped Terraform change before any deletion. Do not infer that a denied listing means the bucket is empty.
4. Review a fresh destroy plan: `rtk proxy terraform -chdir=cloud/terraform plan -destroy -out=/tmp/grp01-destroy.tfplan` followed by `rtk proxy terraform -chdir=cloud/terraform show /tmp/grp01-destroy.tfplan`. Check that only GRP01 project resources are selected. The S3 bucket resources have no `force_destroy`, so any objects or versions require a separately approved, bucket-specific emptying step before apply. For the log bucket only, the proposed command is `rtk proxy aws s3 rm s3://cloud-trail-logs-grp01 --recursive --profile cloud --region eu-west-3` **after** archive verification and approval. Recreate the plan after any out-of-band change.
5. Apply the reviewed plan only after Anouar approves the final resource list: `rtk proxy terraform -chdir=cloud/terraform apply /tmp/grp01-destroy.tfplan`. Confirm Terraform state, AWS resource listings through the IAM profile, and billing afterwards. The Secrets Manager secret enters its configured recovery period; confirm its pending-deletion state and when billing stops rather than assuming immediate removal.
6. After local evidence review, delete the local cluster with `rtk proxy kind delete cluster --name grp01` only if Anouar also approves local teardown. Verify with `rtk proxy kind get clusters`.

The commands are a plan, not proof of deletion. Recheck live state, prices, and dependencies immediately before executing them.
